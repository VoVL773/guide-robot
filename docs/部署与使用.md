# 部署与使用

本文面向当前单包 `guide_voice`。目标实机环境是 Ubuntu 24.04 / aarch64、Python 3.12 和 ROS 2 Jazzy；仓库不是包含底盘、模型和机器人平台的一键安装包。

## 准备依赖

先安装 ROS 2 Jazzy 和 colcon，再准备以下外部组件：

| 组件 | 用途与来源 |
|---|---|
| `interaction_msgs`、`lyre_msgs` | 由机器人平台提供的消息与服务定义，需要加载对应工作区 |
| 平台 TTS / ASR / 音频服务 | 播报、平台识别以及 `/lyre/audio_stream` 音频输入 |
| `robot_controller` | 厂商底盘 SDK，须提供 `robot_controller.chassis.KnewbotChassisNav` |
| 千问或兼容服务 | 提供 `/v1/chat/completions`，模型需支持当前请求中的 `chat_template_kwargs` |
| faster-whisper 与模型 | 本地麦克风识别；使用模型名时可能需要下载权重 |

Ubuntu 上的基础 Python 依赖可以通过系统包安装：

```bash
sudo apt install python3-numpy python3-yaml python3-psutil python3-opencv
```

faster-whisper 请按目标 aarch64 环境与 CTranslate2 兼容情况安装，使用能访问 ROS 系统包的 Python 3.12 环境。仓库未锁定其版本，本次未验证全新环境安装，不建议直接混用 Conda 和系统 ROS Python。

验证平台及 SDK 是否能被当前 Python 找到：

```bash
source /opt/ros/jazzy/setup.bash
source /实际路径/xos/setup.bash
export ROBOT_CONTROLLER_SRC=/实际路径/robot_controller/src
python3 -c 'import rclpy, interaction_msgs, lyre_msgs; from robot_controller.chassis import KnewbotChassisNav; print("依赖导入成功")'
```

`ROBOT_CONTROLLER_SRC` 应指向包含 `robot_controller` Python 包的源码父目录，代码默认值是 `/home/nvidia/robot_controller/src`。即使关闭导航，语音节点启动时仍会导入 SDK 和平台消息包。

## 构建

在仓库根目录执行，并保留根目录变量供后续命令使用：

```bash
export GUIDE_ROBOT_ROOT="$PWD"
source /opt/ros/jazzy/setup.bash
source /实际路径/xos/setup.bash
cd "$GUIDE_ROBOT_ROOT/guide_ws"
colcon build --packages-select guide_voice
source install/setup.bash
```

每个新终端都需要重新加载 ROS、平台及本项目的 `setup.bash`。本文的“实际路径”需要按部署环境替换。

普通 `colcon build` 会把 Python 与配置安装到 `install/`：修改源码或包内 YAML 后重新构建，再重启节点。使用 `--symlink-install` 时，Python 源码通常可以直接生效，但配置是否软链接需实际检查，不能一概假定所有 YAML 都无需构建。

## 先验证文本聊天

设置实际模型地址和模型名；以下值为示例：

```bash
ros2 run guide_voice voice_chat --ros-args \
  -p enable_nav:=false \
  -p enable_mic:=false \
  -p auto_relocalize:=false \
  -p startup_goto_standby:=false \
  -p qwen_base_url:=http://127.0.0.1:8000/v1 \
  -p qwen_model:=YOUR_MODEL_NAME
```

另一个已加载 ROS 环境的终端发送：

```bash
ros2 topic pub --once /guide_voice/chat std_msgs/msg/String "{data: '你好'}"
ros2 service list -t
```

预期能看到节点接收文本；若模型和 `/intelligent_interaction/tts/play` 服务正常，应生成回复并播报。没有播报时分别检查模型请求日志与 TTS 服务，不能仅凭节点进程存在判断链路已通过。

## 实机导航

先完成底盘地图与 POI 配置，并检查定位、底盘健康、维护模式、麦克风与相机状态。默认地点文件是 [`places.yaml`](../guide_ws/src/guide_voice/config/places.yaml)，字段含义见 [README](../README.md#配置地点)。

建议先启用导航但关闭启动自动重定位、回待命点和麦克风，通过文本逐步验证：

```bash
ros2 run guide_voice voice_chat --ros-args \
  -p enable_nav:=true \
  -p enable_mic:=false \
  -p auto_relocalize:=false \
  -p startup_goto_standby:=false \
  -p chassis_host:=192.168.11.10 \
  -p chassis_port:=9090 \
  -p qwen_base_url:=http://127.0.0.1:8000/v1 \
  -p qwen_model:=YOUR_MODEL_NAME
```

将底盘地址和模型参数替换为本机配置；此模式仍会连接底盘，收到导航文本后会执行运动。确认启动日志中的“地点配置 / 可去地点 / 主线点”正确后，再发送当前地图存在的目标，例如原现场：

```bash
ros2 topic hz /ob_camera_head/depth/image_raw
ros2 topic pub --once /guide_voice/chat std_msgs/msg/String "{data: '带我去跆拳道馆'}"
```

相机缺失或数据过期时，当前实现不会因此自动判定前方有障碍；不能把这类状态当成防撞正常。

完成文本导航、短距离往返与播报验证后，可去掉调试覆盖参数以使用默认麦克风和启动行为。当前 launch 仅声明以下四个参数：

```bash
ros2 launch guide_voice voice_chat.launch.py \
  qwen_base_url:=http://127.0.0.1:8000/v1 \
  qwen_model:=YOUR_MODEL_NAME \
  qwen_api_key:=EMPTY \
  greet_text:="你好，我是小郑"
```

`EMPTY` 只适用于无需真实凭据的服务。需要鉴权时使用实际凭据，避免把它提交或录入公开日志。其他节点参数请通过 `ros2 run ... --ros-args -p ...` 设置，不能直接当作未声明的 launch 参数使用。

## 配置更新

默认地点文件来自包的安装目录；修改源码配置后，在 `guide_ws` 中重新运行：

```bash
colcon build --packages-select guide_voice
source install/setup.bash
```

然后停止并重启语音节点。也可以在原有 `ros2 run` 参数中增加 `-p places_file:=/实际路径/places.yaml`，直接加载外部文件；外部文件修改后仍需重启。

地图 POI 名称变化时，同步核对 `aliases`、`main_line`、`branches`、`standby`，以及 `asr_hotwords`、`asr_initial_prompt`。工作台当前有自己的固定配置路径，不会自动跟随节点的 `places_file` 参数。

## 测试

从仓库根目录运行：

```bash
python3 -m unittest discover -s guide_ws/src/guide_voice/test -v
python3 -m unittest discover -s web_monitor -p test_monitor.py -v
```

2026-11-19 实际执行结果：47 项导航测试和 13 项工作台测试全部通过。导航测试注入假底盘；工作台测试使用测试 HTTP 服务与模拟状态。二者均不验证真实地图、语音模型、硬件接口或整机运动。
