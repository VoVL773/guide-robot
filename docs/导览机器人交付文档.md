## 1. 项目目标与范围

让机器人以自然语音接待访客，并把访客带到场馆内的指定地点：

1. 听到访客说话（或收到文本），能闲聊，也能识别「带我去跆拳道馆」这类指令；
2. 按场馆物理顺序逐点导航，去程、回程都不跳点；
3. 到点后语音提示并询问是否还需要服务，听到「没事了」自动回待命点；
4. 全程受底盘健康、定位状态、前向防撞三层保护；
5. 提供只读的网页监测看板，便于现场观察，不具备控制能力。

**不在范围内**：底盘 SLAM 建图/定位算法、地图编辑器、平台级 TTS/ASR 服务、消防巡检业务。

## 4. 关键设计

### 4.1 配置驱动：地图是唯一真源

`config/places.yaml` 只描述「叫什么、按什么顺序走」，坐标全部来自底盘 `GET /api/core/navigation/v1/poi`：

```yaml
standby: 乐知院
aliases:        # 语音别名 -> 地图点位名
main_line:      # 必须按物理顺序排列
  - 乐知教育
  - 核心力量跑酷
  - 创想谷
  - 厕所
  - 跆拳道馆
branches: {}    # 支线 -> 挂接的主线点（本图无支线）
transfer_points: [start_point]   # 只作中转，不作为目的地
```

设计取舍：

- **不维护第二份坐标**，避免配置与地图漂移；
- 地图上不存在的点位自动被过滤，换图不会崩；
- 换场馆只改 YAML，不改代码。

### 4.2 路线规划：主线逐点、不跳点、可反向

`Navigator.plan_route()` 读取当前位姿，把当前位置投影到主线段上，得到「已到哪个点」，再按目标在主线上的下标决定方向：

- 去程：`ceil(投影位置) → 目标下标`，逐点经过；
- 回程：`floor(投影位置) → 目标下标`，反向逐点经过；
- 支线：先到挂接点，再进支线；从支线出发时先回挂接点；
- 投影点在前方时不会误判为「已到达」，中途恢复不会跳过拐角。

每一段都用**规划坐标 + 行进朝向**下发 `move_to(x, y, yaw, flags=0)`，不依赖 POI 里统一为 0 的 yaw。

### 4.3 可靠性：三层门控 + 明确的失败语义

每次下发运动前依次检查：

1. **健康**：解析 DTC 严重程度。A/B 类阻断，C 类（如 WiFi 未连接）只告警；
2. **定位**：`slam_status` 必须是 0，且位姿 `confidence > 0` 连续 3 秒；
3. **健康复查**：防止恢复等待期间出现新故障。

定位异常的分级恢复：

| slam\_status | 含义            | 动作                                            |
| ------------ | ------------- | --------------------------------------------- |
| 0            | 正常            | 放行                                            |
| 1/2/3/5      | 丢失/降级/异常/待重定位 | `recover_localization`，初值优先吸附 3m 内点位，其次近期可信位姿 |
| 4            | 空闲（服务未启动）     | `start_localization` 重载当前地图，30s 冷却            |
| 6/7/8        | 底盘正在恢复        | 只等待，不重复打断                                     |

其他保护：

- **通信不确定不重发**：`move_to` PUT 超时视为「可能已接单」，先取消并确认，避免双任务；
- **到点校验**：动作报成功还需位姿在 0.35m 内；定位异常时 1m 内按到达处理；
- **前向防撞**：深度图 1.2m 阈值 + 无效像素占比，连续 3 帧确认后取消；重发前要求前方连续清空 1.5s；
- **重试上限**：每段最多 3 次，整条路线共享 180s 预算；
- **AEB**：导航前开启，任务结束且取消确认后才关闭；取消未确认则保留 AEB。

### 4.4 语音交互状态机

```
听到文本
  ├─ 命中地点别名 + 有「去/到/回」等动词 → 直接导航
  ├─ 只表达意愿（"我想练跆拳道"）→ 询问"需要我带你去吗？"
  │     ├─ 肯定 → 导航
  │     └─ 否定 → 结束
  ├─ 已在目的地，听到"没事了/回去吧" → 回待命点
  └─ 其他 → 交给千问闲聊
```

工程细节：

- 导航期间 `_navigating=True`，新语音直接丢弃，避免半路改目标；
- 播报期间关闭麦克风（`hold`），防止机器人听见自己的声音；
- ASR 热词 + 初始提示限定在本图地点，降低「创想谷」等新词的误识别；
- 滤除「乐知院、核心力量跑酷、创想谷……」这类热词整段吐出的幻听。

### 4.5 性能与体验优化（2026-11-15）

| 项目     | 优化前       | 优化后             | 实现                         |
| ------ | --------- | --------------- | -------------------------- |
| 底盘限速   | 0.3 m/s   | 0.6 m/s（参数可调）   | `Navigator._apply_speed()` |
| 到点停顿   | 约 4.4s    | 功能已跑通，新耗时未记录 | 跨段复用「定位连续正常」记录             |
| 单程 22m | 124\~135s | 路线已跑通，新耗时未记录 | 以上两项                       |

停顿的根因不是 `_LEG_SETTLE_S=1.0`，而是**每段重新等 3 秒定位稳定**。现在记录最近一次「正常且可信」的观测（4s 内有效）和连续正常的起点，下一段直接沿用；一旦出现异常立即清零，安全语义不变。

### 4.6 只读监测看板

`web_monitor` 与导览进程完全独立：

- 只提供 `GET /api/status`、`GET /api/logs`、`GET /api/frame`；
- 所有写方法返回 405，其他路径 404；
- 不创建发布者、不调用服务或 Action；
- 电量优先读底盘 `battery/pack` 的 `isCharging`，不用电流正负推断；
- 日志脱敏（API key / Bearer / password），内存最多 200 条；
- 相机预览约 3 FPS、不录像、不落盘。

## 5. 模块协作与契约

### 5.1 一次导览的调用链

```
ASR/文本
  → VoiceChatNode._handle
    → PlaceBook.resolve              取点位名与播报名
    → Navigator.check_ready          定位可恢复 + 健康 + AEB
    → Navigator.go(poi, 180s, guard)
      → plan_route                   生成 Leg(name,x,y,yaw) 列表
      → 每段: _check_health → _check_localization → _dispatch → _run_action
      → 返回 success/failure/blocked/timeout/localization/health/network
    → _speak(到达文案) / 失败话术
```

### 5.2 关键接口契约

| 调用方       | 被调用方       | 接口                                                                                                                              | 失败语义             |
| --------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| Node      | PlaceBook  | `resolve(text) / describe() / main_line / branches / standby`                                                                   | 返回 None 表示不是地点指令 |
| Node      | Navigator  | `check_ready() -> (bool, 话术)`                                                                                                   | False 时直接播报，不下发  |
| Node      | Navigator  | `go(poi, timeout, guard) -> str`                                                                                                | 7 种返回码，逐一对应播报    |
| Navigator | 底盘 REST    | `move_to / get_action_status / cancel_action / get_robot_health / get_localization_status / set_speed_params / set_aeb_control` | 超时按「不确定」处理，不重发   |
| Node      | TTS        | `TtsService(append/query)`                                                                                                      | 播报失败只告警，不阻断导航    |
| Navigator | FrontGuard | `blocked() / distance() / zero_ratio()`                                                                                         | 无新数据视为不阻断        |

### 5.3 交付后的协作分工建议

| 角色    | 负责内容         | 交接物                    |
| ----- | ------------ | ---------------------- |
| 现场/点位 | 底盘建点、确认物理顺序  | POI 名称清单、现场通道说明        |
| 语音    | 热词、话术、ASR 模型 | `places.yaml`、节点参数     |
| 导航/底盘 | 定位恢复、限速、故障码  | `navigation.py`、底盘固件版本 |
| 测试    | 往返实测、异常场景    | 测试日志、偏差记录              |
| 运维    | 启动、监测、重启策略   | 本文章节 7                 |

```bash
ros2 launch guide_voice voice_chat.launch.py
# 或带参数
ros2 run guide_voice voice_chat --ros-args \
  -p enable_mic:=true \
  -p max_moving_speed:=0.6 \
  -p nav_timeout:=180.0
```

常用参数：

| 参数                     | 默认        | 说明                            |
| ---------------------- | --------- | ----------------------------- |
| `enable_mic`           | true      | 关闭后只接受 `/guide_voice/chat` 文本 |
| `enable_nav`           | true      | 关闭后只保留聊天                      |
| `max_moving_speed`     | 0.6       | 底盘限速（m/s），0 表示不改              |
| `nav_timeout`          | 180.0     | 整条路线预算（秒）                     |
| `track_id`             | 0         | 非 0 改走底盘轨道导航（本图未用）            |
| `front_guard_stop`     | 1.2       | 前向停车距离（m）                     |
| `front_guard_retries`  | 3         | 被防撞取消后的重试次数                   |
| `auto_relocalize`      | true      | 启动时按待命点自动重定位                  |
| `startup_goto_standby` | true      | 启动后先回待命点                      |
| `places_file`          | 包内 config | 自定义地点配置路径                     |

## 9. 使用边界与运行条件

1. 定位依赖底盘激光 SLAM，长走廊尽头、玻璃/反光区域置信度会下降；低置信度时系统会停车等待而不是硬走。
2. 底盘 AEB 在自主导航中不生效，安全性依赖本项目的深度防撞；深度相机被遮挡会失去这层保护。
3. 限速是底盘全局参数，修改后手动驾驶同样生效。
4. 语音只支持单轮地点指令 + 简单确认，复杂多意图（「先去厕所再去跆拳道馆」）不支持。
5. 根目录 `README.md` 已同步为当前单包交付方案，启动入口为 `guide_voice/voice_chat.launch.py`。

***

## 10. 演进思路与取舍

1. **从多包 Action 架构收敛到单包**：早期拆成 interfaces/core/nav/head/voice/orchestrator 六个包，实际只有一台车、一条路线，包间契约的维护成本高于收益；现在用普通类调用，链路更短、故障点更少。
2. **配置与代码分离**：点位、顺序、别名全部外置，换场地不需要改 Python。
3. **宁可停车也不冒险**：定位不稳、故障码阻断、通信不确定时一律停下并播报，不做「重发碰运气」。
4. **只读监测**：现场需要看状态，但不希望看板成为第二个控制入口，因此所有写接口直接拒绝。
5. **保留但不启用轨道模式**：底盘支持轨道导航（`track_id`），当前地图以点对点逐段更可控，留参数作为备选。
